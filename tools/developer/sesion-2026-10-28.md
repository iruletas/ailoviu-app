## Bugs resueltos

### Error de importación de `SecureStore`
`prefs_provider.dart` intentaba importar desde `services/secure_store.dart`,
pero el archivo vive en `core/secure_store.dart`. Build roto.
**Fix:** Corregir la ruta a `../core/secure_store.dart`.

### Error de Gradle
`Your project's Gradle version (8.9.0) is lower than Flutter's minimum supported version of 8.14.0`.
**Fix:** Cambiar el wrapper a `gradle-8.14.3-all.zip`.

### Error de Kotlin
`Your project's Kotlin version (2.1.0) is lower than Flutter's minimum supported version of 2.2.20`.
**Fix:** Cambiar el plugin de Kotlin en `settings.gradle.kts` a `2.2.20`.

### Error de recursos (`mipmap/ic_launcher` not found)
`flutter create` no generó los recursos porque un step anterior del
workflow lo omitía si encontraba ciertos archivos.
**Fix:** El workflow ahora *siempre* corre `flutter create` para
generar los faltantes, y restaura el `build.gradle.kts` con
`git checkout` para no perder la firma.

### APK "paquete no válido"
Android rechazaba la instalación de la nueva APK sobre la anterior.
**Causa:** La app instalada era la versión `0.1.62`, firmada con un
keystore anterior o distinto.
**Fix:** Desinstalar la versión vieja y compilar exclusivamente para
`arm64` con `minSdk = 23`. El log confirmó que la firma de release
estaba correcta (`CN=Ailoviu...`).

## Decisiones

- **Sin Double Ratchet.** Se descartó implementar el protocolo
  completo de Signal a mano por la alta probabilidad de bugs y el
  tiempo que tomaría. Se mantiene el cifrado estático (X25519 +
  AES-GCM) que ya está implementado y es seguro para dos personas.
- **`lib/games/`**. Se confirmó que la lógica de juegos va en esta
  carpeta, no en `core/`.
- **Auto-versionado.** Se devolvió el versionado `0.1.{run_number}`
  porque al desarrollador le resultaba más cómodo para iterar rápido.

## Aprendizajes

- Compilar para una sola arquitectura (`arm64`) reduce el tamaño y
  evita conflictos de firma en Android.
- El auto-versionado con `run_number` cuenta los fallos de CI, pero
  para un proyecto personal es más útil que el versionado manual.
- `flutter create` no sobrescribe archivos existentes, pero sí
  genera los recursos faltantes.
